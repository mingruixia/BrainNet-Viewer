# 曲面细分并另存NV

[English](Surface_Subdivision.en.md) · [手册](../manual/zh-CN/index.md)

使用 **Tools → Subdivide Surface to NV...** 将一个支持的曲面生成更稠密的新ASCII `.nv`。这是改变几何的操作，不会替换当前Scene或源文件。

1. 选择一个`.nv`、`.pial`、`.mesh`、BYU `.g`、MNI/BIC `.obj`、`.mz3/.mz3.gz`或`.gii/.gii.gz`，点击**Review**。
2. 选择1–3级。每级对每条无向三角边只生成一个共享中点，并把每个三角面替换为4个。一级面片数4倍、二级16倍、三级64倍。坐标是线性中点；不平滑、不保持曲率、不配准、不重采样、不生成法线、不简化或修复。
3. 核对来源/指纹与预测数量。默认上限为500万顶点和1000万三角面片，超限在分配/发布前拒绝；大网格需要较多内存。
4. 空间、单位和备注可选；留空记为`unknown`，不推断或转换MNI/mm。确认颜色、标量图、材质、法线、标签及已激活的GIfTI变换均不会传递。
5. **Save New .nv...**仅新建文件，采用17位有效数字、精确读回复核、来源/外部数组指纹及禁止覆盖发布。需要时再通过**Surface Mesh**加载。

## 范围与旧版关系

这是有明确数学定义的现代线性细分工具。旧能力审计rendering-detail requirements主要指渲染细节控件及其保存；未找到旧版“细分后另存”的算法。因此不宣称它重建旧渲染质量模式，也不承诺保持标量/属性对应。已有节点、连边或体数据可能与新几何不再对应，需另行建立对应关系。

第二行`#`为JSON来源记录：来源/依赖哈希、输入输出数量、逐级数量、算法、可选声明和时间。分享前检查绝对路径。最终指纹检查不是文件系统快照；未作GPU/多核提速声明、Settings/Scene Schema修改、完整回归或跨平台认证。
